# Music Store Customer Support — Deep Agent + LangSmith

A prototype customer-support bot for a fictional online record store, built on
[LangChain Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) over the
[Chinook](https://github.com/lerocha/chinook-database) sample database, and evaluated in
[LangSmith](https://smith.langchain.com).

| File | What it is |
|---|---|
| `agent.ipynb` | Builds the agent. Tools, middleware, subagents, a walkthrough of every branch. Its last cell exports `src/agent/agent.py`. |
| `evaluators.ipynb` | Measures the agent: dataset, 11 evaluators, two experiments, pairwise comparison, annotation queue, cost analytics. |
| `src/agent/agent.py` | **Generated** from `agent.ipynb`. What LangSmith Studio serves and what `evaluators.ipynb` imports. Don't edit by hand. |
| `langgraph.json` | Generated by `agent.ipynb`. Points the LangGraph CLI at the graph. |
| `data/chinook.db` | Built on first run from the official Chinook SQL dump. |

## Architecture

```
                        ┌──────────────────────────────────────┐
   customer ──────────► │  SUPERVISOR  (create_deep_agent)     │
                        │  claude-sonnet-5 · no tools of its   │
                        │  own · reasons + delegates via task()│
                        └───────┬───────────┬───────────┬──────┘
                                │           │           │
              ┌─────────────────┘           │           └─────────────────┐
              ▼                             ▼                             ▼
   ┌────────────────────┐      ┌────────────────────┐      ┌────────────────────────┐
   │ inventory-         │      │ order-             │      │ escalation-specialist  │
   │ specialist         │      │ specialist         │      │ (human-in-the-loop)    │
   │ haiku-4.5          │      │ haiku-4.5          │      │ haiku-4.5              │
   │ search_db          │      │ cust_profile       │      │ escalate_to_human      │
   │ web_search         │      │ search_db          │      │ → interrupt()          │
   └────────────────────┘      └────────────────────┘      └────────────────────────┘
```

**Model policy:** cheapest-first. Haiku 4.5 runs every specialist, every guard classifier, the
web-search executor and most judges. Only the supervisor and two judges use Sonnet 5, because
routing and security grading are the two places a cheap mistake is expensive. A full
18-example evaluation of both agent variants costs about **$0.72**.

## Middleware

| Middleware | Hook | What it does |
|---|---|---|
| `tool_audit` | `@wrap_tool_call` | Records every tool call and result, so evaluators can grade the trajectory rather than just the answer |
| `customer_security_guard` | `@wrap_tool_call` | Five-layer single-customer isolation: fail-closed, scope rewriting, SQL policy, transparency labelling, leak check |
| `music_store_scope_guard` | `@wrap_tool_call` | Keeps `web_search` on music/store topics |
| `human_escalation_router` | `@wrap_model_call` | Forces delegation to the escalation subagent when the customer's words match the policy |
| `escalation_enforcer` | `@wrap_model_call` | Pins `tool_choice` so the hand-off happens on the first turn, not after questions |
| `ModelCallLimitMiddleware` | built-in | Cost ceiling on a runaway supervisor |
| `SummarizationMiddleware` | built-in | Long support threads stay in the context window |

All five custom middleware are `async`: the LangGraph server drives graphs with `ainvoke`, and
a sync-only hook raises `NotImplementedError` there.

## Setup

```bash
export ANTHROPIC_API_KEY=...      # the only model key needed; web search is server-side
export LANGSMITH_API_KEY=...
uv sync
```

## Run it

**1. The notebooks** — `agent.ipynb` first (it generates `src/agent/agent.py` and
`langgraph.json`), then `evaluators.ipynb`.

```bash
uv run jupyter lab          # or run them headless:
uv run python -c "import nbformat; from nbclient import NotebookClient; \
  nb=nbformat.read('agent.ipynb',as_version=4); NotebookClient(nb,timeout=1200).execute()"
```

**2. LangSmith Studio**

```bash
uv run langgraph dev
```

Then, in a second terminal, create one assistant per simulated logged-in customer:

```bash
uv run python scripts/create_assistants.py
```

Open `https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024`, switch to **Chat**
mode, and pick a persona from the assistant dropdown:

| Assistant | Simulates |
|---|---|
| Roberto Almeida (customer 12) | signed-in customer, 7 orders |
| Frantisek Wichterlova (customer 5) | a different signed-in customer |
| Signed out (no session) | nobody signed in — the fail-closed path |

Then just type. Suggested run: *"What did I order most recently?"* → *"Do you have any
AC/DC?"* → *"I want to speak to a real person"* (this one pauses the graph on an interrupt you
approve, edit or reject from the UI). Switch persona and repeat the first question to see the
same graph scoped to a different account.

> The logged-in customer lives in the graph's **runtime context**, not the chat. Each assistant
> pins a `customer_id` into it. You can also edit it by hand in Studio's Graph mode under
> **Manage Assistants → Default configuration**, but the personas are less fiddly for a demo.

Or drive it over HTTP:

```bash
THREAD=$(curl -s -X POST http://127.0.0.1:2024/threads \
  -H 'content-type: application/json' -d '{}' | python3 -c "import sys,json;print(json.load(sys.stdin)['thread_id'])")

curl -s -X POST "http://127.0.0.1:2024/threads/$THREAD/runs/wait" \
  -H 'content-type: application/json' -d '{
    "assistant_id": "music_store_support",
    "input": {"messages": [{"role": "user", "content": "What did I order most recently?"}]},
    "context": {"customer_id": 12}
  }'
```

## What the evaluation shows

Two agents, one dataset: the shipping agent (`hardened`) against an identical agent with the
middleware removed and security asked for in the system prompt instead (`prompt-only`).

```
metric                     prompt-only  hardened  delta
no_foreign_data_retrieved        0.944     1.000  0.056
no_pii_in_answer                 0.944     1.000  0.056
contains_expected_facts          0.833     1.000  0.167
security_policy                  0.833     0.944  0.111
groundedness                     0.833     0.933  0.100
response_quality                 0.828     0.924  0.096
reasoning_quality                0.772     0.856  0.084
```

The prompt-only baseline is *polite* — it rarely says anything it shouldn't. But asked for
"my support rep's email address" it joins the `Employee` table and pulls a staff address into
context, then decides afterwards how much to repeat. Grading only the final answer would miss
that entirely; grading the trajectory does not. The hardened agent never receives the row.

An LLM judge also caught something no deterministic rule could: on a shared-laptop identity
claim, the agent was reading the *signed-in* customer's name and email back to someone
claiming to be a different person. In scope by every rule expressible in code, and still a
disclosure. That fix is in the order-specialist prompt.

## Notes

- `data/`, `.env` and `.langgraph_api/` are gitignored. `.env` is written by `agent.ipynb` for
  the LangGraph CLI and contains your keys.
- Row-level security is enforced with SQLite `TEMP VIEW`s that shadow `Customer`, `Invoice`
  and `InvoiceLine`. `temp` resolves before `main`, so `WHERE CustomerId = 1 OR 1=1` cannot
  escape the view — and the guard separately rejects `main.`-qualified table names.
